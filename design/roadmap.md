## Обзор

MVP полностью завершён: 5 итераций, 143 клиента, 5 маршрутов, импорт из Excel, печать, CRUD клиентов.

Фаза 2 — переход от «работает» к «удобно пользоваться каждый день». Фокус на стабильности, мобильности и аналитике.

**Принцип:** каждая итерация — самостоятельная ценность. Можно остановиться после любой.

## Итерация 6 — Пауза клиента

> Клиенты уходят в отпуск, закрываются на ремонт. Сейчас приходится удалять из маршрута и потом вручную возвращать.

**Покрывает:** Спек §3.1 (`active: boolean`), Фаза 3 («Пауза клиента»)

| # | Задача | Приоритет |
|---|--------|-----------|
| 6.1 | Кнопка «Пауза / Активировать» в таблице клиентов | Критично |
|     | — Toggle `isActive` в store (поле уже есть в модели) | |
|     | — Визуал: бейдж «На паузе» / «Активен» уже есть, нужна кнопка | |
| 6.2 | Скрытие паузных клиентов из маршрутов | Критично |
|     | — Паузный клиент не показывается в маршруте дня | |
|     | — Не предлагается в «+ Добавить точку» | |
|     | — Счётчики и сводка пересчитываются без паузных | |
| 6.3 | Фильтр «Показать паузных» в таблице клиентов | Важно |
|     | — По умолчанию: показывать всех (с визуальным различием) | |
|     | — Фильтр: «Только активные» / «Только на паузе» / «Все» | |
| 6.4 | Восстановление после паузы | Важно |
|     | — Снятие паузы → клиент снова появляется в маршрутах своих дней | |
|     | — Позиция в маршруте: в конец (старая позиция не сохраняется) | |

**Зависимости:** нет (инфраструктура isActive уже в модели)
**Критерий приёмки:**
- Пауза клиента — 1 клик из таблицы
- Паузный клиент не появляется в маршруте и печати
- Снятие паузы — клиент возвращается в маршруты

## Итерация 7 — Статистика

> Админ хочет понимать объёмы: сколько ковриков за неделю, сколько метров, какие дни загружены больше.

**Покрывает:** Фаза 3 («Статистика за период»)

| # | Задача | Приоритет |
|---|--------|-----------|
| 7.1 | Недельная сводка | Критично |
|     | — Итого за неделю: точки, коврики по размерам, метраж | |
|     | — Разбивка по дням (таблица/бар-чарт) | |
| 7.2 | Загрузка по дням | Важно |
|     | — Визуализация: какой день самый загруженный | |
|     | — Подсказка для балансировки маршрутов | |
| 7.3 | Клиентская статистика | Желательно |
|     | — Топ клиентов по метражу | |
|     | — Распределение по частоте (пирог/бар) | |

**Зависимости:** нет
**Критерий приёмки:**
- Недельная сводка доступна в 1 клик
- Видно, какой день самый загруженный

## Итерация 8 — Оптимизация маршрутов

> Порядок объезда сложился исторически. Оптимизация сэкономит Илье время и бензин.

**Покрывает:** Фаза 3 («Оптимизация маршрутов», «Привязка к карте»)

| # | Задача | Приоритет |
|---|--------|-----------|
| 8.1 | Геокодирование адресов | Критично |
|     | — Привязка координат к каждому клиенту (Nominatim / Yandex Geocoder) | |
|     | — Ручная корректировка на карте | |
| 8.2 | Визуализация маршрута на карте | Критично |
|     | — Leaflet / Yandex Maps | |
|     | — Точки на карте в порядке объезда | |
|     | — Линия маршрута | |
| 8.3 | Алгоритм оптимизации | Важно |
|     | — Nearest neighbor / 2-opt для TSP | |
|     | — Кнопка «Оптимизировать порядок» | |
|     | — Предпросмотр: было / стало | |
|     | — Подтверждение перед применением | |

**Зависимости:** Итерация 6 (паузные клиенты не должны попадать в оптимизацию)
**Критерий приёмки:**
- Маршрут визуализируется на карте
- Оптимизация предлагает лучший порядок, админ подтверждает

## Итерация 9 — История изменений

> Случайно удалил клиента / переставил точки и забыл порядок. Нужна возможность откатить.

**Покрывает:** Фаза 3 («История изменений»)

| # | Задача | Приоритет |
|---|--------|-----------|
| 9.1 | Undo/Redo для маршрутов | Критично |
|     | — Ctrl+Z / кнопка «Отменить» | |
|     | — Стек действий (последние 20) | |
| 9.2 | Лог изменений | Важно |
|     | — Кто/что/когда изменилось | |
|     | — Просмотр истории по клиенту / маршруту | |
| 9.3 | Авто-бекап | Желательно |
|     | — Периодическое сохранение снимков в IndexedDB | |
|     | — Восстановление из снимка | |

**Зависимости:** нет
**Критерий приёмки:**
- Ctrl+Z откатывает последнее действие с маршрутом
- Можно посмотреть, что изменилось за последнюю неделю

## Граф зависимостей

```
Итерация 6 (пауза)       Итерация 7 (статистика)
    │                          │
    ▼                          ▼
Итерация 8 (карта + оптимизация)
    │
    ▼
Итерация 9 (история)
```

Итерации 6, 7 — независимы, можно делать в любом порядке.
Итерация 8 — зависит от 6 (паузные клиенты).
Итерация 9 — можно делать когда угодно.
