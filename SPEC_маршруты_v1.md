# SPEC: Система управления маршрутами
## Сервис аренды грязезащитных ковриков

**Версия:** 2.0
**Дата:** Февраль 2026
**Статус:** Актуальное описание системы

---

## 1. Обзор проекта

### 1.1 Проблема

Управление маршрутами и клиентской базой ведётся в Excel-файле «Илья_новый.xls» со сложной структурой: 11 листов, дублирование данных, ручной подсчёт метража и распределение по дням.

**Ключевые проблемы текущего файла:**

- Данные о клиенте (название, адрес, **размер ковриков**) записаны в одну ячейку произвольным текстом — размер коврика является частью имени клиента. Примеры:
  - `метрополис к. Маркса -2x180, 2x150`
  - `Сбер академия 2х150 коричнев стар`
  - `пальмира Ленина 5- 200 новый 150 нов`
- Распределение по дням дублируется на нескольких листах (лист «Неделя» + листы-фильтры «Понедельник»–«Пятница» + маршрутные листы «ПН»–«ПТ»)
- Порядок объезда задаётся дробными числами (1, 2, 3... 16.5, 27.05, 27.491) — вставки между точками без перенумерации
- Маршрут на день — единый упорядоченный список точек (без деления на блоки/подмаршруты)
- Нет защиты от ошибок: легко потерять клиента, забыть точку, перепутать коврик
- Конечный пользователь (Илья, 55 лет) испытывает затруднения при работе с файлом

### 1.2 Цель

Создать **веб-приложение**, которое:

1. Заменит Excel-файл единым интерфейсом с базой клиентов и маршрутами
2. Будет максимально простым для пользователя 55+ лет
3. Автоматически считает метраж и количество ковриков по дням
4. Позволит менять порядок объезда, переносить клиентов между днями
5. Даст возможность распечатать маршрутный лист (в т.ч. по водителям)
6. Сохраняет данные между сессиями с автоматическим резервным копированием
7. Визуализирует маршрут на карте с оптимизацией порядка объезда
8. Управляет водителями, их графиками и назначениями

### 1.3 Пользователи

**Основной пользователь: Администратор (владелец бизнеса)** — управляет базой клиентов, маршрутами, водителями, формирует маршрутные листы. Работает с компьютера или планшета, локально, одно устройство.

**Вторичный пользователь: Илья (курьер, ~55 лет)** — получает готовый маршрутный лист на день, выполняет объезд. Интерфейс для курьера = печатный лист (максимально крупный шрифт, простая таблица).

- **Критерий для админа:** полное управление базой, маршрутами и водителями через удобный веб-интерфейс
- **Критерий для Ильи:** получить понятный печатный маршрутный лист, разобраться без объяснений

### 1.4 Формат решения

Веб-приложение (React SPA), открывается в браузере. Monorepo с Turborepo — без серверов, без логинов.

## 2. Анализ текущих данных

### 2.1 Структура файла

| Листы | Назначение | Описание |
|-------|-----------|----------|
| Неделя | Мастер-таблица | 143 клиента: частота, флаги по дням, метраж |
| ПН, ВТ, СР, ЧТ, ПТ | **Маршрутные листы** | Упорядоченные точки с номером остановки и раскладкой ковриков. |
| Понедельник–Пятница | Фильтры по дням | Дублирование мастер-таблицы, отфильтрованное по флагу дня |

### 2.2 Структура записи клиента

| Поле | Как хранится сейчас | Пример |
|------|-------------------|--------|
| Название + адрес + коврики | Одна ячейка, свободный текст | `метрополис к. Маркса -2x180, 2x150` |
| Общий метраж (кв.м) | Число | `6.690` |
| Кол-во ковриков по размерам | Отдельные столбцы: 180, 150, 60×80, 400, 250 | `2, 2, 0, 0, 0` |
| Частота (раз/нед) | Число 1–7 | `3` |
| Дни обслуживания | Флаги 0/1 | `ПН=1, ВТ=0, СР=1, ЧТ=0, ПТ=1` |
| Порядок в маршруте | Дробное число (per day) | `16.5`, `27.491` |
| Цвет/тип коврика | Вшит в текст названия | `коричневый`, `серый`, `новый`, `старый` |
| Доп. информация | Вшита в текст | `3-ий вход`, `резаный` |

### 2.3 Статистика базы

| Показатель | Значение |
|-----------|----------|
| Всего клиентов | 143 |
| Общий метраж (все коврики) | ~98.5 кв.м |
| Размеры ковриков | Динамические (настраиваемые) |
| Точек в ПН | 58 точек, ~141 кв.м |
| Точек во ВТ | 58 точек, ~148 кв.м |
| Точек в СР | 49 точек, ~132 кв.м |
| Точек в ЧТ | 56 точек, ~139 кв.м |
| Точек в ПТ | 59 точек, ~138 кв.м |

**Распределение по частоте:**

| Частота | Клиентов | Примечание |
|---------|---------|------------|
| 5 раз/нед | 8 | Каждый день |
| 4 раза/нед | 4 | ПН–ЧТ |
| 3 раза/нед | 24 | Обычно ПН/СР/ПТ |
| 2 раза/нед | 44 | Разные комбинации |
| 1 раз/нед | 63 | Самая большая группа |

### 2.4 Особенности маршрутов

**Плоский список:** Маршрут на каждый день — один упорядоченный список точек без деления на подмаршруты или блоки. В исходном Excel (листы ПН–ПТ) маршрут представлен как единая последовательность остановок.

**Дробная нумерация:** Вставки между точками делаются через дробные числа (16.5 = между 16 и 17, 27.491 = после 27.49). В приложении это решается drag & drop — без дробей.

## 3. Модель данных

### 3.1 Клиент (Client)

```
{
  id: string                // UUID
  originalName: string      // "метрополис к. Маркса -2x180, 2x150" — исходная строка из Excel
  name: string              // "Метрополис" — чистое название
  address: string           // "К. Маркса, д.5"
  mats: [                   // массив ковриков
    { sizeId: "180", qty: 2 },
    { sizeId: "150", qty: 2 }
  ]
  frequency: number         // 1–7
  days: DayOfWeek[]         // [0, 2, 4] — ПН, СР, ПТ
  dayReplacements?: Partial<Record<DayOfWeek, number>>  // кол-во замен по дням
  notes: string             // "3-ий вход, резаный"
  isActive: boolean         // true/false (на паузе или нет)
  lat?: number              // координаты для карты (геокодирование)
  lng?: number
}
```

### 3.2 Маршрут дня (DayRoute)

```
{
  day: DayOfWeek            // 0–6 (ПН–ВС)
  stops: [                  // упорядоченные точки
    { id: string, clientId: string, completed: boolean, driverId?: string },
    ...
  ]
}
```

> `DayOfWeek` = `0 | 1 | 2 | 3 | 4 | 5 | 6` (Понедельник — Воскресенье)

### 3.3 Водитель (Driver)

```
{
  id: string                // UUID
  name: string              // "Илья"
  phone: string             // телефон
  isActive: boolean         // активен/неактивен
  workDays: DayOfWeek[]     // рабочие дни [0, 1, 2, 3, 4]
}
```

### 3.4 Размер коврика (MatSizeConfig)

```
{
  id: string                // "180", "150", "custom-1"
  label: string             // "180 (120×150)"
  area: number              // 2.07 кв.м
}
```

> Размеры ковриков полностью настраиваемые — добавление, редактирование, удаление через UI. При удалении размера, который используется клиентами, показывается диалог с возможностью замены на другой размер.

### 3.5 Запись лога изменений (ChangeLogEntry)

```
{
  id: string
  type: 'route' | 'client'
  action: string            // 'add' | 'remove' | 'update' | ...
  description: string
  timestamp: number
}
```

### 3.6 Резервная копия (Backup)

```
{
  id: string
  timestamp: number
  clientCount: number
  stopCount: number
  data: { clients, routes, matSizes, drivers, settings }
}
```

## 4. Экраны приложения

### 4.1 Главный экран — Маршрут на сегодня

**При открытии приложение сразу показывает маршрут на текущий день** — это то, зачем админ открывает приложение в 90% случаев.

- Вверху: переключатель дней — 7 кнопок (ПН | ВТ | СР | ЧТ | ПТ | СБ | ВС), текущий день подсвечен
- Рядом с каждым днём: мини-бейдж с количеством клиентов
- **Дашборд дня (блок вверху, на видном месте):**
  - Количество точек и общий метраж
  - **Коврики по размерам** — отдельные карточки с количеством по каждому размеру
  - **Сводка по водителям** — кто сколько точек и ковриков везёт
- Фильтр по водителю — показать только точки конкретного водителя

### 4.2 Маршрут на день (список точек)

**Под дашбордом — список точек в порядке объезда:**

- Каждая точка — карточка: `№ | Название | коврики (компактный формат) | водитель`
- **Поле поиска** прямо над списком — фильтрует точки по названию/адресу
- Чекбокс «✓ Выполнено» напротив каждой точки
- Кнопки ↑↓ для перемещения + drag & drop

**Действия на экране маршрута:**

**Изменить порядок:** кнопки ↑↓ или drag & drop. Нумерация пересчитывается автоматически (без дробей).

**Добавить точку в маршрут:**
1. Кнопка «+ Добавить точку» → модальное окно со списком клиентов (только те, кто ещё НЕ в маршруте)
2. Поиск по названию в модалке
3. Клик на клиента → выбор позиции: «Вставить после точки №___» или «В конец»
4. Клиент появляется в маршруте в выбранной позиции

**Убрать точку из маршрута:** кнопка ✕ на карточке → подтверждение → точка убрана. Клиент НЕ удаляется из базы.

**Перенести точку в другой день:**
1. Кнопка «Перенести» на карточке точки
2. Выбор дня (ПН–ВС) + позиция в новом маршруте
3. Точка убирается из текущего дня и появляется в новом

**Назначить водителя:**
- Выбор водителя на каждой карточке точки (dropdown)
- Показываются только водители, работающие в этот день
- **Массовое назначение:** кнопка для назначения водителя на все/выбранные/нераспределённые точки сразу

**Отображение названий:** В маршруте точка показывается **в привычном формате из Excel** (например, «Монетка гоголя 103 -180»), чтобы Илья узнавал клиентов.

### 4.3 База клиентов

**Управление всеми клиентами:**

- Таблица с поиском (поиск по названию и адресу)
- Столбцы: название, адрес, коврики (визуальные бейджи), метраж, частота, дни, статус
- Фильтры: по дню недели, по частоте, по размеру коврика, по статусу
- Двухстрочный компактный формат карточек
- Индикатор геокодирования (аномалии подсвечены)

**Действия:**
- «Добавить клиента» — форма:
  - Название (текст)
  - Адрес (текст) + кнопка геокодирования
  - Коврики (inline-редактирование, выбор из настраиваемых размеров)
  - Частота (1–7)
  - Дни (чекбоксы: ПН ☐ ВТ ☐ СР ☐ ЧТ ☐ ПТ ☐ СБ ☐ ВС ☐), количество ограничено частотой
  - Количество замен по дням (если отличается от общего)
  - Примечания (текст)
- Редактировать / Удалить / Поставить на паузу

### 4.4 Печатный маршрутный лист

**Это основной рабочий инструмент Ильи.** Формат критичен.

Генерируется кнопкой «Печать» на экране маршрута → CSS @media print → браузерная печать.

**Два режима печати:**
1. **Общий лист** — все точки дня одним списком
2. **По водителям** — отдельная страница на каждого водителя + страница «Нераспределённые» (если есть)

- Заголовок: день недели + дата печати (+ имя водителя при печати по водителям)
- Таблица с динамическими столбцами размеров (только используемые размеры)
- Строка итогов в конце (количество по каждому размеру + метраж)
- Крупный шрифт: **14pt минимум**
- Чёрно-белая (экономия тонера)
- Поле «✓» — пустой квадрат для ручной отметки
- Корректные разрывы страниц между водителями

### 4.5 Карта маршрута

**Визуализация маршрута на интерактивной карте (Leaflet):**

- Маркеры остановок на карте с нумерацией
- Линия маршрута между точками
- **Оптимизация порядка объезда:**
  - OSRM-интеграция — оптимизация по реальным дорогам
  - Fallback на прямые расстояния (Haversine) если OSRM недоступен
  - Диалог с показом экономии расстояния в процентах
  - Применение оптимизированного порядка к маршруту

### 4.6 Управление водителями

**Полный CRUD водителей:**

- Список водителей с именем, телефоном, статусом
- Добавление / редактирование / удаление водителя
- **График работы** — выбор рабочих дней (ПН–ВС) для каждого водителя
- Водители с нерабочим днём не показываются в dropdown назначения на этот день

### 4.7 Управление размерами ковриков

**Настраиваемый справочник размеров:**

- Список размеров с названием и площадью
- Добавление новых размеров
- Редактирование существующих
- Удаление с диалогом подтверждения — показывает, какие клиенты используют этот размер, с возможностью замены

### 4.8 Статистика

**Аналитика по неделе:**

- Сводная таблица: загрузка по дням (точки, метраж, коврики по размерам)
- Визуальная диаграмма загрузки — bar chart по метражу и количеству точек
- Статистика по клиентам

### 4.9 Обратная связь

- Кнопка «Обратная связь» в верхней панели
- Ссылка на Telegram для связи с разработчиком

## 5. UX-требования

### 5.1 Админ-интерфейс

| Параметр | Требование |
|----------|-----------|
| Шрифт | 14–16px основной, 18px+ заголовки |
| Кнопки | Чёткие, подписанные, touch target ≥ 44px |
| Навигация | Вкладки сверху, максимум 2 клика до любой функции |
| Действия | Автосохранение, подтверждение удаления |
| Undo/Redo | Ctrl+Z / Ctrl+Y, история 20 шагов |
| Тема | Dark mode (по умолчанию) + полноценный Light mode |
| Планшеты | Адаптивная вёрстка для lg: breakpoint |
| Анимации | Поддержка prefers-reduced-motion |

### 5.2 Печатный лист для курьера (Илья, 55 лет)

| Параметр | Требование |
|----------|-----------|
| Шрифт | **Минимум 14pt**, заголовки 18pt+ |
| Формат | Таблица на A4, чёрно-белая |
| Информация | Номер, название, коврики по размерам, метраж, галочка |
| Итоги | Сумма по каждому размеру + общий метраж |
| Поле «✓» | Пустой квадрат для ручной отметки |
| По водителям | Отдельные страницы с разрывами |

### 5.3 Доступность (Accessibility)

- ARIA-атрибуты на интерактивных элементах (aria-label, aria-pressed, aria-current)
- Focus-visible стили на полях ввода
- Touch target ≥ 44px на всех кнопках (включая закрытие диалогов)
- Глобальная поддержка prefers-reduced-motion
- Error Boundary с graceful fallback

### 5.4 Взаимодействие

- Перемещение точек: **кнопки ↑↓** (основной способ) + drag & drop (@dnd-kit)
- Удаление: подтверждение «Точно удалить? ДА / НЕТ»
- **Автосохранение** — никаких кнопок «Сохранить»
- Undo/Redo — откат последних изменений (маршруты + клиенты)
- Ошибки: понятным языком, с подсказкой что делать

## 6. Рабочие сценарии (User Stories)

### US-1: Подготовка ковриков на завтра (вечерний ритуал)

**Ситуация:** Вечером админ готовит стопку ковриков для завтрашнего маршрута.

**Шаги:**
1. Открывает приложение → видит маршрут на сегодня
2. Переключает на завтрашний день (клик по вкладке)
3. **Сразу видит дашборд:** карточки по каждому размеру + сводка по водителям
4. Готовит коврики по списку, распределяя по водителям

**Критерий:** Сводка по размерам — это **первое, что видно** на экране маршрута, не нужно скроллить.

### US-2: Печать маршрутного листа (утро)

**Ситуация:** Утром админ печатает маршрутный лист.

**Шаги:**
1. Открывает приложение → маршрут на сегодня уже на экране
2. Жмёт «Печать»
3. Получает отдельные листы по каждому водителю (или общий лист)
4. Раздаёт водителям

**Критерий:** От открытия до печати — **2 клика**.

### US-3: Быстрый поиск клиента в маршруте

**Ситуация:** Звонит клиент «Монетка на Кирова», нужно быстро найти его в сегодняшнем маршруте.

**Шаги:**
1. На экране маршрута вводит «монетка» или «кирова» в поле поиска
2. Список фильтруется, видна нужная точка
3. Может убрать из маршрута / перенести / посмотреть детали

**Критерий:** Найти клиента в маршруте — **менее 5 секунд**.

### US-4: Новый клиент — добавить в базу и в маршрут

**Ситуация:** Подписали нового клиента, нужно добавить его в систему и вставить в маршрут на среду между точками 15 и 16.

**Шаги:**
1. Переходит в «Базу клиентов» → «Добавить клиента»
2. Заполняет: название, адрес, коврики (из настраиваемого списка размеров), частота, дни
3. Адрес геокодируется автоматически (или вручную по кнопке)
4. Переходит на маршрут Среды → «+ Добавить точку»
5. Находит нового клиента в списке, выбирает «Вставить после точки №15»
6. Клиент встаёт на позицию 16, остальные сдвигаются

**Критерий:** Вставка в середину маршрута — **без перетаскивания через 40 позиций**.

### US-5: Клиент просит перенести на другой день

**Ситуация:** «Мы на ремонте в среду, приезжайте в четверг на этой неделе.»

**Шаги:**
1. На маршруте Среды находит клиента (поиск)
2. Жмёт «Перенести» на карточке точки
3. Выбирает «Четверг» и позицию (или «В конец»)
4. Точка исчезает из среды, появляется в четверге

**Критерий:** Перенос между днями — **3–4 клика**.

### US-6: Убрать точку на эту неделю (клиент закрыт / отпуск)

**Ситуация:** Клиент предупредил, что на этой неделе их не будет.

**Шаги:**
1. Находит клиента в маршруте (поиск)
2. Жмёт ✕ → подтверждение «Убрать из маршрута на сегодня?»
3. Точка убрана, нумерация пересчитана
4. Клиент **остаётся в базе** и в маршрутах на следующие недели

**Важно:** «Убрать из маршрута» ≠ «Удалить клиента». Это разные действия.

### US-7: Проверка — все ли клиенты на месте

**Ситуация:** Админ хочет убедиться, что ни один клиент не потерялся при переносах.

**Шаги:**
1. Открывает «Базу клиентов»
2. Фильтрует по дню (напр. «Среда»)
3. Видит всех клиентов, у которых среда в расписании
4. Сравнивает с маршрутом среды — если кто-то выпал, добавляет обратно

**Критерий:** В базе клиентов видно, включён ли клиент в маршрут на каждый из своих дней.

### US-8: Оптимизация маршрута

**Ситуация:** Маршрут на день составлен, но порядок объезда не оптимален — много лишних километров.

**Шаги:**
1. Открывает страницу «Карта» — видит маршрут на карте
2. Жмёт «Оптимизировать» → OSRM рассчитывает оптимальный порядок
3. Видит процент экономии расстояния
4. Применяет оптимизированный порядок

**Критерий:** Автоматическая оптимизация по реальным дорогам в 1 клик.

### US-9: Назначение водителей на маршрут

**Ситуация:** На среду работают 2 водителя, нужно распределить 49 точек между ними.

**Шаги:**
1. Открывает маршрут среды
2. Использует «Назначить водителя» → массовое назначение на все нераспределённые точки
3. Или назначает поштучно через dropdown на каждой карточке
4. Видит сводку: «Илья — 25 точек, 70 кв.м | Сергей — 24 точки, 62 кв.м»

**Критерий:** Массовое назначение в 2 клика. Сводка по водителям всегда видна.

### US-10: Обнаружение аномалий геокодирования

**Ситуация:** Адрес клиента геокодирован неправильно — координаты далеко от других точек.

**Шаги:**
1. Система автоматически обнаруживает аномалии (IQR-метод по расстояниям)
2. В таблице клиентов аномальные адреса подсвечены
3. Админ может перегеокодировать адрес или исправить вручную

**Критерий:** Подозрительные адреса видны без ручной проверки каждого.

## 7. Технические решения

### 7.1 Стек

| Компонент | Технология | Почему |
|-----------|-----------|--------|
| Сборка | Vite + Turborepo | Быстрая сборка, monorepo |
| Фронтенд | React 19 + TypeScript strict | Типобезопасность |
| Стилизация | Tailwind v4 + Shadcn/ui | Быстрая разработка, dark/light mode |
| Состояние | Zustand + persist | Простое, с localStorage persistence |
| Undo/Redo | Zundo (temporal middleware) | 20 шагов истории |
| Маршруты | React Router | Навигация SPA |
| Drag & Drop | @dnd-kit | Сортировка остановок |
| Карты | Leaflet | Визуализация маршрута |
| Оптимизация | OSRM (внешний) | Маршрутизация по реальным дорогам |
| Геокодирование | Nominatim (OpenStreetMap) | Адрес → координаты |
| Иконки | Lucide React | Единый стиль |
| Бекапы | idb-keyval (IndexedDB) | Автоматическое резервное копирование |
| Печать | CSS @media print | Нативная печать через браузер |

### 7.2 Хранение данных

**localStorage (Zustand persist)** — основное хранилище:

| Store | localStorage key | Назначение |
|-------|-----------------|------------|
| Клиенты | `kover-clients` | База клиентов |
| Маршруты | `kover-routes` | Маршруты + selectedDay |
| Водители | `kover-drivers` | Список водителей |
| Размеры | `kover-mat-sizes` | Справочник размеров ковриков |
| Лог изменений | `kover-changelog` | История действий (макс. 200 записей) |
| Настройки | `kover-settings` | Город геокодирования, sync настройки |

**IndexedDB** — автоматические резервные копии:
- Периодическое сохранение полного состояния
- Хранится до 20 последних бекапов
- UI для просмотра, восстановления и удаления бекапов

**Версионирование хранилищ:**
- Каждый store имеет версию (routes: v3, drivers: v2 и т.д.)
- Миграции между версиями (например, добавление СБ/ВС при обновлении v2→v3)

### 7.3 Миграция данных

При первом запуске — импорт из Excel-файла:

**Что парсится из названий клиентов:**
- Название организации, адрес, размеры ковриков, цвет/тип, примечания

**Экран проверки после импорта:**
- Таблица: «Исходная строка из Excel» → «Что распознали: название / адрес / коврики»
- Строки с проблемами подсвечены
- Возможность быстро поправить
- Кнопка «Всё верно, запустить»

## 8. Реализованные фазы

### Фаза 1 — MVP ✅

Маршрут на день, сводка, переключатель дней (ПН–ПТ), список точек, поиск, печать, порядок (↑↓ + drag & drop), добавление/удаление/перенос точек, чекбокс «Выполнено», импорт Excel, localStorage.

### Фаза 2 — Управление ✅

База клиентов (CRUD), таблица с фильтрами, редизайн формы клиента, inline-редактирование ковриков.

### Фаза 3 — Карта и оптимизация ✅

Визуализация маршрута на карте (Leaflet), оптимизация порядка (OSRM + fallback), геокодирование (Nominatim с привязкой к городу), обнаружение аномалий (IQR-метод), перегеокодирование.

### Фаза 4 — Надёжность данных ✅

Undo/Redo (Zundo, 20 шагов), лог изменений (макс. 200 записей), авто-бекап в IndexedDB (макс. 20 копий), восстановление из бекапа.

### Фаза 5 — Водители ✅

CRUD водителей, график работы по дням, назначение водителя на остановку, массовое назначение, фильтрация маршрута по водителю, сводка загрузки по водителям, печать по водителям.

### Фаза 6 — Качество и UX ✅

Настраиваемые размеры ковриков, количество замен по дням, поддержка выходных (СБ+ВС), dark/light mode, адаптация под планшеты, accessibility (ARIA, focus, touch targets, reduced-motion), Error Boundary, lazy loading, обратная связь (Telegram).
